# FeedbackCounterTabletMotion (動態検知版)

- compileSdk / targetSdk: 36
- CameraX の ImageAnalysis を使って **動いている領域** を抽出し、
  ブロブ(塊)ごとに **ID を付けて追跡** します。
- 通過カウントは「**出現側** と **消失側**」で判定します（中央線の横切りだけでは数えません）。
- ネイティブライブラリ（MediaPipe 等）を使わないため、**16KB page size** 問題を避けやすい構成です。

## 画面
- アンケート: 3ボタン（よかった/普通/悪かった）をタップで加算（ビープ音）
- 人数: カメラの縮小プレビュー（画面高の約1/4）＋水色ボックス（ID付き）＋カウンタ
- 設定: 右上のハンバーガーメニュー →「設定」でダイアログ表示（Endpoint 設定、送信方式、結果クリアなど）。スクロール対応、閉じる・戻る・ダイアログ外タップで閉じられます。

## Endpoint (任意)
設定ダイアログの Endpoint に Webhook / GAS URL を入力して、以下の送信方式を選択します。

- **送信しない**: 自動送信を停止します。画面上部の `SYNC` からの手動送信は可能です。
- **カウントが変化したタイミングで送信**: アンケート回答・通過人数の加算・カウンタのクリア直後に送信します。従来版と同じ初期設定です。
- **定期的に送信**: 指定間隔（1～60分、初期値5分）で最新の全カウンタ値を送信します。カウント変化時は送信しません。

自動送信設定は DataStore に保存されるので、アプリ再起動後も維持されます。
定期送信はアプリ起動後または設定変更後から間隔を計測し、最初の送信は指定間隔後です。

**重要**: 定期送信はアプリの ViewModel が動作している間に限ります。Android がアプリを終了したりバックグラウンド実行を制限した場合、指定周期の送信を保証できません。端末再起動時の自動送信やアプリ終了後の送信は実装していません。

送信処理では DataStore の最新カウンタ値を一括取得します。通信失敗時は最終同期欄にエラーを記録しますが、再送キューやオフライン蓄積はありません。

```json
{
  "good": 1,
  "normal": 2,
  "bad": 0,
  "passL2R": 3,
  "passR2L": 1,
  "ts": 1734630000000
}
```

## Android Studio
1. フォルダを Android Studio で開く
2. 初回は Gradle/依存関係がダウンロードされます
3. 実機で実行（カメラ権限を許可）

## 前バージョンからの更新

- 既存の DataStore キー名を維持しており、アンケート回答・人数カウンタ・Endpoint・タイトルはそのまま引き継ぎます。
- 自動送信設定キー `sync_mode` / `sync_interval_min` が追加されます。
- 既存インストールでは自動送信は従来どおり **カウント変化時** が初期値です。
- 設定はタブを廃止し、右上のハンバーガーメニューからダイアログで開きます。ダイアログ内はスクロール可能です。
